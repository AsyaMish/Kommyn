# Kommyn
Приложение для личного учета коммунальных услуг
# Техническое задание на приложение «Коммуналка»

## 1. Общие сведения

**Название:** «Коммуналка».  
**Назначение:** личное приложение для учёта коммунальных услуг по двум адресам, с возможностью ведения помесячных и годовых записей, расчёта сумм, отметок об оплате и передаче показаний, формирования отчётов, архивации и обмена данными через файлы.  
**Пользователь:** один (владелец). Онлайн-синхронизация не требуется.  
**Платформы:** Windows (десктоп) и Android (мобильное устройство). Установка и обновление — через репозиторий GitHub (сборки).  
**Режим работы:** локальный, без сервера. Все данные хранятся на устройстве. Перенос данных между устройствами — вручную через файлы JSON/CSV/ZIP.

---

## 2. Термины и определения

- **Адрес** — «Рабочая 23» или «Рабочая 23А».
- **Услуга** — газ, вода, свет, мусор, интернет, телевидение, налоги.
- **Запись** — одна операция учёта: услуга + адрес (если применимо) + период (месяц/год).
- **Период** — календарный месяц (для помесячных услуг) или календарный год (для годовых услуг).
- **Техническая дата** — дата и время создания/последнего изменения записи в системе. Используется для сортировки истории и умного слияния JSON. Пользователю может показываться справочно.
- **Дата оплаты** — фактическая дата платежа. Влияет на архивацию. По умолчанию — текущая дата, редактируется.
- **Дата передачи показаний** — справочная дата, не влияет на архивацию, выгрузку и системную логику. По умолчанию — текущая дата, редактируется.
- **Долг/Аванс** — одно числовое поле со знаком: положительное значение — аванс (переплата), отрицательное — долг. Рядом галочка «использован долг/аванс».
- **Галочка «показания переданы»** — независимая отметка для услуг с показаниями.
- **Галочка «оплачено»** — независимая отметка для всех услуг. Для системы именно она означает, что операция оплачена (не сумма факта оплаты).

---

## 3. Платформы и установка

- **Windows:** установщик или портативная версия (на усмотрение разработчика, но без обязательной установки сторонних зависимостей).
- **Android:** APK для установки.
- **Обновления:** через GitHub Releases. Пользователь скачивает новую версию и устанавливает поверх.
- **Мобильная версия:** полностью адаптивная, без горизонтальной прокрутки, с нижней навигацией и крупными элементами управления.

## 4. Модель данных

### 4.1. Справочники

**Дома:**
- `Рабочая 23`
- `Рабочая 23А`

**Услуги:**
- `Газ` — помесячная, по адресам, с показаниями.
- `Вода` — помесячная, по адресам, с показаниями.
- `Свет` — помесячная, по адресам, с показаниями.
- `Мусор` — помесячная, по адресам, без показаний (тариф × жильцы).
- `Интернет` — помесячная, без адресов, два подпункта: `Мобильный`, `Домашний`.
- `Телевидение` — годовая, без адресов.
- `Налоги` — годовая, только для `Рабочая 23А`, с подполями: `Дом`, `Земля`, `Машина`.

### 4.2. Запись

Каждая запись содержит:

- `id` — уникальный идентификатор.
- `service` — услуга.
- `address` — адрес (для услуг, где применимо; иначе `null`).
- `subservice` — подпункт (для интернета: `Мобильный`/`Домашний`; иначе `null`).
- `period_year` — год.
- `period_month` — месяц (1–12) для помесячных; `null` для годовых.
- `record_type` — `monthly` или `annual`.
- `previous_readings` — предыдущие показания (для газа, воды, света). Число или `null`.
- `current_readings` — текущие показания (для газа, воды, света). Число или `null`.
- `tariff` — тариф (для газа, воды, света, мусора). Число.
- `residents_count` — количество жильцов (для мусора). Целое число.
- `tax_house` — сумма налога на дом (для налогов). Число.
- `tax_land` — сумма налога на землю (для налогов). Число.
- `tax_car` — сумма налога на машину (для налогов). Число.
- `debt_advance` — долг/аванс. Число со знаком (`+` аванс, `−` долг). Может быть `null`.
- `debt_advance_closed` — булево: галочка «использован долг/аванс».
- `fact_payment` — фактическая сумма оплаты. Число.
- `payment_date` — дата оплаты. Дата.
- `readings_submitted_date` — дата передачи показаний. Дата (справочно).
- `flag_readings_submitted` — булево: «показания переданы».
- `flag_paid` — булево: «оплачено».
- `technical_date` — дата и время создания/последнего изменения записи в системе.

### 4.3. Уникальный ключ записи

Для сопоставления при умном слиянии и предотвращения дублей используется комбинация:

- `service`
- `address` (или `null`)
- `subservice` (или `null`)
- `period_year`
- `period_month` (или `null` для годовых)

Если запись с таким ключом уже существует — при слиянии сравниваются `technical_date` и остаётся более свежая.

## 5. Бизнес-логика

### 5.1. Общие правила

- Все суммы хранятся в рублях, с точностью до копеек (или до целых — на усмотрение разработчика, но единообразно).
- Все даты — в локальном часовом поясе пользователя.
- Удаление любой записи — только после подтверждения: «Вы хотите удалить запись?» с кнопками «Удалить» и «Отменить».
- При редактировании записи обновляется `technical_date`.

### 5.2. Газ, вода, свет (помесячно, по адресам)

**Поля карточки:**
1. Предыдущие показания — предзаполнено, редактируется.
2. Текущие показания — вводится вручную.
3. Тариф — предзаполнен, редактируется.
4. Расход = текущие − предыдущие (справочно, не редактируется).
5. Долг/Аванс — предзаполнено, редактируется. Рядом галочка «использован долг/аванс».
6. Сумма = расход × тариф − аванс + долг (формула, не редактируется).
7. Факт оплаты — по умолчанию равен «Сумме», редактируется.
8. Дата оплаты — по умолчанию текущая, редактируется.
9. Дата передачи показаний — по умолчанию текущая, редактируется.
10. Галочки: «показания переданы», «оплачено».

**Подтягивание предыдущих показаний:**
- Берутся последние введённые (непустые) показания из предыдущих записей по этой же услуге и адресу.
- Если предыдущих записей нет — поле пустое, вводится вручную.
- Пропущенные месяцы не обнуляют показания: берётся последнее заполненное значение.

**Подтягивание тарифа:**
- Берётся последний действующий тариф по этой услуге (независимо от адреса).
- Если пользователь меняет тариф вручную в текущей записи, новое значение сохраняется как действующий тариф и подтягивается в последующие месяцы до следующего ручного изменения.
- История тарифов хранится.

**Подтягивание долга/аванса:**
- Берётся из предыдущего месяца по этой же услуге и адресу.
- Если в предыдущем месяце стояла галочка «использован долг/аванс» — подтягивается `0` (пусто).
- Если предыдущий месяц пропущен — долг/аванс всё равно передаётся из последней записи, где он был, пока не стоит галочка.
- Галочка снимается при редактировании — долг/аванс снова становится активным.

### 5.3. Мусор (помесячно, по адресам)

**Поля карточки:**
1. Количество жильцов — предзаполнено: `Рабочая 23` — 1, `Рабочая 23А` — 4. Редактируется.
2. Тариф — предзаполнен, редактируется.
3. Сумма = количество жильцов × тариф − аванс + долг (не редактируется).
4. Долг/Аванс — предзаполнено, редактируется. Рядом галочка «использован долг/аванс».
5. Факт оплаты — по умолчанию равен «Сумме», редактируется.
6. Дата оплаты — по умолчанию текущая, редактируется.
7. Галочка «оплачено».

**Подтягивание количества жильцов:**
- Логика как у тарифа: изменили значение в текущем месяце — в следующих месяцах подтягивается новое значение до следующего изменения.

**Подтягивание долга/аванса:**
- Аналогично газу/воде/свету: из предыдущего месяца по этому адресу, с учётом галочки.

### 5.4. Интернет (помесячно, без адресов, подпункты «Мобильный» и «Домашний»)

**Поля карточки:**
1. Последняя оплата — справочно. Подтягивается последний непустой `fact_payment` из предыдущих записей по этому подпункту.
2. Долг/Аванс — предзаполнено, редактируется. Рядом галочка «использован долг/аванс».
3. Факт оплаты — вводится вручную.
4. Дата оплаты — по умолчанию текущая, редактируется.
5. Галочка «оплачено».

**Подтягивание долга/аванса:**
- Из предыдущей месячной записи по этому подпункту, с учётом галочки. При пропусках — передаётся дальше, пока не стоит галочка.

**Факт оплаты для справки «Последняя оплата»:**
- Подтягивается последнее непустое значение, даже если были пропуски.

### 5.5. Телевидение (раз в год, без адресов)

**Поля карточки:**
1. Последняя оплата — справочно. Подтягивается последний непустой `fact_payment` из предыдущих годовых записей.
2. Долг/Аванс — предзаполнено, редактируется. Рядом галочка «использован долг/аванс».
3. Факт оплаты — вводится вручную.
4. Дата оплаты — по умолчанию текущая, редактируется.
5. Галочка «оплачено».

**Подтягивание долга/аванса:**
- Из последней записи по телевидению, где был долг/аванс, с учётом галочки. При пропущенных годах — передаётся дальше, пока не стоит галочка.

### 5.6. Налоги (раз в год, только «Рабочая 23А»)

**Поля карточки:**
1. Подполя: `Дом`, `Земля`, `Машина` — суммы вводятся вручную.
2. Общая сумма налога = дом + земля + машина (автоматически, не редактируется).
3. Предыдущая оплата — справочно. Подтягивается предыдущий год с разбивкой по подполям и общей суммой.
4. Долг/Аванс — один на общую сумму налога. Предзаполнено, редактируется. Рядом галочка «использован долг/аванс».
5. Факт оплаты — вводится вручную.
6. Дата оплаты — по умолчанию текущая, редактируется.
7. Галочка «оплачено».

**Подтягивание долга/аванса:**
- Из последней годовой записи по налогам, где был долг/аванс, с учётом галочки. При пропущенных годах — передаётся дальше, пока не стоит галочка.

**Предыдущая оплата:**
- Берётся из предыдущего года (даже если там `0`). Разбивка по подполям и общая сумма.

### 5.7. Логика «Долг/Аванс» (общая для всех услуг)

- Одно поле на запись. Значение со знаком: `+` — аванс, `−` — долг.
- Визуально: аванс — зелёным цветом без знака, долг — красным с минусом.
- В формуле: аванс уменьшает сумму к оплате, долг увеличивает.
- Рядом галочка «использован долг/аванс».
- Пока галочка не стоит, значение передаётся из записи в запись (из месяца в месяц, из года в год) независимо от пропусков и наличия факта оплаты.
- Когда галочка поставлена:
  - В текущей записи значение остаётся видимым для отчётности.
  - В следующую запись значение не передаётся (там будет `0`/пусто).
- Если галочку снять при редактировании — значение снова становится активным и продолжает передаваться.
- Долг и аванс одновременно невозможны: в поле всегда одно число.

### 5.8. Галочки

- **«Показания переданы»** — только для газа, воды, света. Независимая отметка.
- **«Оплачено»** — для всех услуг. Именно она означает для системы, что операция оплачена. Сумма факта оплаты сама по себе не означает оплату.
- Обе галочки могут стоять независимо.

### 5.9. Даты

- **Дата оплаты** — влияет на архивацию (записи старше 1 года). По умолчанию текущая, редактируется.
- **Дата передачи показаний** — справочная, ни на что не влияет. По умолчанию текущая, редактируется.
- **Техническая дата** — создаётся/обновляется автоматически. Используется для сортировки истории и умного слияния JSON.

### 5.10. Пропущенные месяцы/годы

- Если месяц не заполнен, при заполнении следующего:
  - Предыдущие показания берутся из последнего месяца, где они были введены.
  - Факт оплаты для помесячных услуг (газ, вода, свет, мусор, интернет) подтягивается строго из предыдущего месяца; если там пусто — `0`.
  - Долг/аванс передаётся дальше, пока не стоит галочка.
- Для годовых услуг (ТВ, налоги):
  - Предыдущая оплата берётся за предыдущий год, даже если `0`.
  - Долг/аванс передаётся из последней записи, где был, пока не стоит галочка.

## 6. Пользовательский интерфейс

### 6.1. Навигация

- **Телефон:** нижняя панель: `Содержание`, `История`, `Отчёты`, `Архив`, `Настройки`.
- **Компьютер:** боковая или верхняя панель с теми же разделами.

### 6.2. Главный экран «Содержание»

- Список услуг, изначально свёрнуты: `Газ`, `Вода`, `Свет`, `Мусор`, `Интернет`, `Телевидение`, `Налоги`.
- Нажатие на услугу разворачивает вкладки адресов:
  - `Газ`, `Вода`, `Свет`, `Мусор` — вкладки `23` и `23А`.
  - `Интернет` — подпункты `Мобильный`, `Домашний` (без адресов).
  - `Телевидение` — без адресов.
  - `Налоги` — только `23А`.
- Вверху экрана — переключатель месяца и года. По умолчанию — текущий месяц.
- Внутри вкладки/подпункта — карточка операции (см. п. 6.3).

### 6.3. Карточка операции

Отображает поля, соответствующие услуге (см. раздел 5).  
Кнопки: `Сохранить`, `Удалить` (с подтверждением).  
При редактировании из истории — те же поля, доступно изменение и удаление.

### 6.4. Вкладка «История»

- Список всех записей.
- Сортировка по умолчанию: по `technical_date` от свежих к старым. Переключатель на «от старых к свежим».
- В строке списка: услуга, адрес (если есть), дата оплаты, фактическая сумма, метки «показания переданы» и «оплачено» (если стоят).
- Фильтры:
  - По меткам: «не оплачено», «не переданы показания» — независимо, можно выбрать одну, другую или обе.
  - По адресу.
  - По услуге.
  - По дате (диапазон).
- Нажатие на запись — открывает карточку для редактирования/удаления.
- Массовый выбор чекбоксами. Массовые действия: `Удалить`, `Архивировать`, `Выгрузить` (с выбором формата CSV или JSON).

### 6.5. Вкладка «Отчёты»

**Конструктор отчётов:**
- Выпадающие списки (без drag-and-drop) и на компьютере, и на телефоне.
- Поля для выбора:
  - Измерения: адрес, услуга, период (месяц/год/диапазон).
  - Значения: начисленная сумма (по формуле), факт оплаты, долг/аванс.
  - Фильтры: метки, даты.
- Типы отчётов: сводный, сравнительный, детализация.

**Отчёт по умолчанию при открытии вкладки:**
- Одна таблица.
- Строки — услуги.
- Столбцы — две сдвоенные группы: `Предыдущий месяц` и `Текущий месяц`. В каждой группе две колонки: `23 факт оплаты` и `23А факт оплаты`.
- Под каждым столбцом — общая сумма по всем услугам отдельно по 23 и по 23А.
- Внизу — общий итог за месяц по двум адресам.
- Годовые услуги (налоги, ТВ) появляются только в месяце фактической оплаты; при выгрузке за год без разбивки — в общей сумме.

### 6.6. Вкладка «Архив»

- Архивы по годам.
- Автоархивация при запуске приложения: все записи с `payment_date` старше 1 года (от текущей даты) перемещаются в архив соответствующего года. Галочка «оплачено» не важна.
- Из истории архивные записи исчезают полностью.
- Выгрузка/загрузка архива: выбор формата JSON или CSV, упаковка в ZIP.
- При загрузке архив попадает в раздел «Архив» с нужным годом.
- Разархивация:
  - Целиком: записи возвращаются в историю, архив за год удаляется, если опустел.
  - Частично: выбор отдельных месяцев или набора месяцев; выбранные записи возвращаются в историю, архив за год сохраняется с оставшимися записями.
- Запись, добавленная вручную с датой оплаты старше 1 года, сначала попадает в историю, а при следующем запуске приложения уходит в архив.

### 6.7. Вкладка «Настройки»

- Управление тарифами (история тарифов по услугам).
- Количество жильцов по адресам.
- Импорт/экспорт JSON — два режима: полная замена и умное слияние.
- Импорт/экспорт CSV — два режима: полная замена и умное слияние.
- Скачать пустой CSV-шаблон со всеми полями.
- Сброс данных (с подтверждением).

---

## 7. Импорт/экспорт

### 7.1. JSON

- Экспорт: все записи в одном JSON-файле, включая `technical_date`.
- Импорт:
  - **Полная замена:** текущая база стирается, загружается новая из файла.
  - **Умное слияние:**
    - Для каждой записи из файла ищется совпадение по уникальному ключу (п. 4.3).
    - Если запись есть в базе и в файле — сравниваются `technical_date`; остаётся более свежая.
    - Если запись есть только в файле — добавляется.
    - Если запись есть только в базе — сохраняется (не удаляется).

### 7.2. CSV

- Экспорт: все поля записи в CSV. Разделитель — на усмотрение разработчика (рекомендуется `;` для совместимости с Excel в русской локали).
- Импорт:
  - **Полная замена:** текущая база стирается, загружается новая из файла.
  - **Умное слияние:** аналогично JSON, по уникальному ключу и `technical_date`. Если `technical_date` в CSV отсутствует, при импорте устанавливается текущая техническая дата (или дата импорта).
- **CSV-шаблон:** скачивается пустой файл с шапкой, содержащей все поля, необходимые для заполнения всех типов карточек:
  - `service`, `address`, `subservice`, `period_year`, `period_month`, `record_type`,
  - `previous_readings`, `current_readings`, `tariff`, `residents_count`,
  - `tax_house`, `tax_land`, `tax_car`,
  - `debt_advance`, `debt_advance_closed`,
  - `fact_payment`, `payment_date`, `readings_submitted_date`,
  - `flag_readings_submitted`, `flag_paid`,
  - `technical_date` (опционально, для слияния).
- Порядок столбцов не критичен для пользователя, но должен быть единым. Пользователь будет пересобирать свою базу по образцу.

### 7.3. ZIP-архивы

- Выгрузка архива за год: ZIP-файл, внутри — файлы JSON и CSV (оба формата).
- Загрузка архива: ZIP-файл с JSON и/или CSV, помещается в раздел «Архив» с соответствующим годом.

## 8. Архивация (детально)

- **Автоматическая:** при запуске приложения все записи, у которых `payment_date` старше 1 года от текущей даты, перемещаются в архив по году `payment_date`. Галочка «оплачено» не учитывается.
- **Ручная:** выбранные в истории записи можно архивировать вручную; они попадают в архив соответствующего года.
- **Хранение:** архивы сгруппированы по годам.
- **Выгрузка:** архив за год в ZIP (внутри JSON и CSV).
- **Загрузка:** ZIP добавляется в архив соответствующего года.
- **Разархивация:**
  - Целиком: все записи года возвращаются в историю; если архив пуст — удаляется.
  - Частично: выбор месяцев (для помесячных) или годовых записей; выбранные возвращаются в историю, остальные остаются в архиве.
- Запись, разархивированная вручную, снова доступна в истории и отчётах.

---

## 9. Отчёты (детально)

- **Конструктор:** выбор измерений, значений, фильтров, типа отчёта.
- **Типы:**
  - Сводный — агрегация по выбранным измерениям.
  - Сравнительный — сопоставление двух периодов, адресов или услуг.
  - Детализация — построчный список записей с выбранными полями.
- **Значения:** начисленная сумма (по формуле), факт оплаты, долг/аванс.
- **Фильтры:** период, адрес, услуга, метки.
- **Отчёт по умолчанию:** таблица, описанная в п. 6.5.
- **Годовые услуги:** в помесячных отчётах появляются только в месяце фактической оплаты; в годовых отчётах — в общей сумме.

## 11. Нефункциональные требования

- **Локальное хранение данных:** встроенная база данных (например, SQLite) или иное локальное хранилище. Без облака.

## 12. Сценарии (примеры)

1. **Заполнение текущего месяца по газу для 23А:**
   - Открыть «Содержание» → «Газ» → вкладка «23А».
   - Предыдущие показания подтянулись автоматически.
   - Ввести текущие показания, проверить тариф.
   - Долг/аванс подтянулся из прошлого месяца.
   - Система рассчитала сумму.
   - Проверить факт оплаты (по умолчанию равен сумме), при необходимости изменить.
   - Поставить галочки «показания переданы» и «оплачено».
   - Сохранить.

2. **Перенос старой базы из Excel:**
   - В настройках скачать CSV-шаблон.
   - Пересобрать свою таблицу по образцу шапки.
   - Импортировать CSV с режимом «умное слияние» или «полная замена».
   - Проверить историю и отчёты.

3. **Архивация:**
   - При запуске приложения записи с датой оплаты старше года автоматически уходят в архив.
   - В разделе «Архив» выбрать год, выгрузить ZIP.
   - При необходимости разархивировать отдельные месяцы.

4. **Построение отчёта:**
   - Открыть «Отчёты». По умолчанию — сравнение предыдущего и текущего месяца по услугам и адресам.
   - Изменить параметры через выпадающие списки, выбрать тип «Детализация», период, услугу.
